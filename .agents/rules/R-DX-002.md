# R-DX-002: Configuración frontend por entorno

## Nombre
**R-DX-002:** Documentar y proteger la configuración Vite expuesta al navegador.

## Alcance
- `frontend/.env.example`, `.gitignore`, `frontend/tsconfig*.json`
- `frontend/src/**/*.ts` y `frontend/src/**/*.tsx`

## Justificación
`App.tsx` lee `import.meta.env.VITE_API_BASE_URL ?? ""`; `frontend/tsconfig.app.json` incluye `"types": ["vite/client"]`, fuente de los tipos de `import.meta.env`. No existe `vite-env.d.ts` y no se requiere crear uno.

## Guía
- Obtén la URL de API de `VITE_API_BASE_URL` y usa fallback `""` para mismo origen, servido mediante el proxy de Vite.
- Documenta las variables en `.env.example`; no pongas valores reales ni secretos.
- Nunca pongas secretos en `VITE_*`: estas variables se exponen al navegador.
- Conserva `.env.local` ignorado y `.env.example` visible para git.
- Verifica: `grep -rnE "VITE_[A-Z_]*(KEY|TOKEN|SECRET|PASSWORD)" frontend --exclude-dir=node_modules` → 0 resultados.
- Verifica: `git check-ignore -v frontend/.env.local` → ignorado; `git check-ignore frontend/.env.example` → sin salida.

## Ejemplo ✅/❌
✅ `const API_BASE_URL = import.meta.env.VITE_API_BASE_URL ?? "";`

❌ `const API_TOKEN = import.meta.env.VITE_API_TOKEN;`

## Excepciones
- Variables Vite no sensibles (por ejemplo, URL pública de API o feature flags públicos) pueden usar el prefijo `VITE_`.

## Validación
- **Fecha:** 2026-11-19; **tarea:** advertencia de secretos en `.env.example` + verificación de `.gitignore`.
- **Comandos:** grep de secretos; `git check-ignore -v frontend/.env.local`; `git check-ignore frontend/.env.example`.
- **Resultado:** cero coincidencias de secretos; `.env.local` ignorado; `.env.example` no ignorado.
- **Refinado:** tipos de `import.meta.env` provienen de `vite/client` en `frontend/tsconfig.app.json`; no se crea `vite-env.d.ts`.
